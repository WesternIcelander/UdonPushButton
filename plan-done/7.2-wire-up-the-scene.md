# 7.2 Wire up the scene

both optional changes were made. The parent is now `PushButtonAssembly`, rotated (0, 180, 0), so the button is at world (0, 1, -0.03) and faces the spawn. The scene was edited by a new idempotent menu item, `Tools/PushButton/Wire Up Scene` (in `PushButtonPlayModeTests.cs`, replacing `Add PushButton To Scene Button`). It renames and rotates the parent, makes sure the child has a `PushButton`, adds a `ButtonActionExample` (no `toggleTarget`) to `PushButtonAssembly`, sets `localPressAxis` (0, 0, -1), `travelDistance` 0.019, `targetBehaviour` (the example's backing UdonBehaviour) and `eventName` `OnButtonPressed` through a `SerializedObject` on the proxy plus `CopyProxyToUdon`, and saves the scene. UdonSharp also set the button's backing `_syncMethod` in the scene (Unity-generated). Temporary code removed from `PushButton.cs`: the `rest local` log (2.1), the `tracking N players` log (5.1), and `handEarlyOutSkips` (6.2). **Harness:** `ButtonPath` is now `PushButtonAssembly/Button`. The tracking-log counts and `CheckSkips` were removed; the tracked-player array checks and the early-out's tip and press checks still cover the same behaviour. The `press unrotated` "1 mm in front of plate" check now uses `buttonParent.TransformPoint(0, 0, 0.011)` instead of a fixed world point. New `AddSceneWiringTest` (first) checks the saved wiring: parent at (0, 180, 0), travel 0.019, axis (0, 0, -1), and the target is the parent's UdonBehaviour running `ButtonActionExample.asset` with `OnButtonPressed`. It then clicks through `ClientSimUdonHelper.Interact()`; one second later there is exactly one `[ButtonActionExample] pressed` log and the button is back at rest. UdonSharp compiled 10 scripts with no errors. Result: `[PushButtonTest] done: 371 passed, 0 failed`, 0 errors. The test log has `scene wiring: desktop click, 1 action logs` and no `[PushButton]` debug lines.
