# 8.4 Make enabling and disabling safe

**Udon order:** a behaviour's first `OnEnable` is dropped by Udon until its first managed update, which then runs `_onEnable` and straight after it `_start`. Udon also delivers custom events (and so `Interact`, `NetPlayClickAnimation` and the manager's calls) to disabled behaviours and inactive objects, so the button guards those itself. **Button:** `Start` is gone. `OnEnable` runs `Initialize()` the first time (the old `Start` work: rest pose, contact box, input mode, and the one no-manager warning plus `DisableInteractive`). Then, if there's a manager, it sets `enabledNow`, calls `ResetToRest()` and registers. `ResetToRest()` is the old `_LeaveRange` body: rest pose rebuilt from the parent, snap to rest, all engagement/click/press state cleared, re-armed. `_LeaveRange()` is now `outOfRange = true` plus `ResetToRest()`. `OnDisable` unregisters, clears `registeredWithManager` and calls `ResetToRest()`. The rest pose relative to the parent is still captured only once (on the first enable), so it's never taken from a pressed position. Registration no longer trusts `Register`'s return value (a dropped call could read a stale one): the manager sets the button's new public `[NonSerialized] registeredWithManager`, and `TryRegister` retries next frame while it's still false. New `IsLive()` (enabled, registered, valid manager, `manager.running`) gates `Interact` and `NetPlayClickAnimation`. `UpdateTrigger` now returns whether it fired, and `_Tick` stops right after a fire if the action disabled the button or the manager. Haptics now play just before the action instead of after, because an action that disables the button clears `localPressHand`. **Manager:** `Register`/`Unregister` are `void`. They set or clear the button's `registeredWithManager` straight away, and while `Update` runs (`ticking`) they go into a pending list (`pendingButtons`/`pendingRegister`, one entry per button holding its latest request) that `ApplyPending()` applies in order after the loop. The tick loop skips buttons whose `registeredWithManager` is false, so a button disabled by an earlier action isn't ticked, and it stops if `running` went false. New public `[NonSerialized] running` is set in `OnEnable` (after `RebuildSlots`) and cleared in the new `OnDisable`. `OnDisable` marks every registered button out of range and calls its `_LeaveRange()`; buttons stay registered, and once the manager is back the range gate brings them back. Re-entrant calls (manager → button tick → action → button `OnDisable` → manager `Unregister`) are safe: Udon saves the program counter, and UdonSharp gives each method its own locals and temporaries (`MethodSymbol` flattens the value-table counters per method). **Harness:** new `AddEnableDisableTest` (after the manager tick test), about 640 checks. It uses a desktop local player, the test action target, and a remote "Toggler" who only counts as VR while a case uses them. Each case below runs three times, turning off the button's GameObject, its parent GameObject and its UdonBehaviour (`SetButtonOn`). (1) Disabled mid-press by the debug fingertip, the toggler's index, a slow local click or a slow networked click: at rest with everything cleared, unregistered, still at rest while off. Enabled again: registered once, a finger still inside doesn't engage, and from the front it presses; the click doesn't carry on or fire, and a new click fires once. (2) A clone that starts off (on its own root holder, never initialized): enabled, then pressed by the local VR index and the toggler's index. (3) A Leaver pressing leaves and a Joiner joins while the button is off: slots match, nothing engaged, the joiner's finger already inside doesn't press, and from the front it does. (4) The parent moved and turned while off: the button comes back at the new rest pose and presses there. (5) Inside the tick, the button's own action (run from its log line through a new one-shot `onAction` hook in `CountActionLogs`): disables itself (at rest, unregistered, no move after), enables another clone (registered once, takes clicks), disables another mid-click (later in the loop: at rest, unregistered, the presser stays at the bottom), and toggles another 20 times (registered once). The registration list (the manager's `buttons`/`buttonCount`) has no holes or duplicates, and the other buttons still take networked clicks. (6) 20 off/on toggles in one test step: registered once, still works. (7) A networked click and an `Interact` while off are ignored. Then (8), for the manager's GameObject and for its UdonBehaviour: the scene button pressed by the debug fingertip and a clone mid-click both snap to rest, `running` goes false, both stay registered, clicks are ignored, and nothing moves while it's off. A player who joins meanwhile is in a slot once it's back, presses, and the fingertip still inside doesn't engage. A listener counts non-test errors and exceptions: 0. The test runs while the earlier tests have left the assembly turned to (35, 120, -70), so it covers a rotated parent too. UdonSharp compiled 11 scripts with no errors. The existing suite also passed with the new code before the test was added (716 passed). Result: `[PushButtonTest] done: 1358 passed, 0 failed` (up from 716), 0 errors. The run now takes about 3.5 min: use `play 420 [PushButtonTest] done|passed` (`TestingAutomation.md` updated).
