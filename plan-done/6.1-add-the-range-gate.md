# 6.1 Add the range gate

`Update` rebuilds the rest pose, then calls `UpdateRangeGate()`. This measures the squared distance from the local player's position to `restWorldPos` (a null local player counts as in range) and returns early when it's beyond `AnimationRangeSqr`. A new private `outOfRange` flag makes the reset run only on the first out-of-range frame. The reset clears every fingertip's engaged and in-front state, the debug fingertip's state and the click (`clickActive`, `clickIsLocal`, `clickPress`). It also zeroes `localPress`, `remotePress` and `localPressHand`, re-arms (the local press is now 0, below the re-arm depth), and snaps `pressAmount` and the transform to rest. Because in-front state is cleared, a fingertip still inside the button when the player comes back has to come in from the front again. `NetPlayClickAnimation`'s own range check (against `transform.position`) is unchanged. **Harness:** new `AddRangeGateTest` (unrotated, after the net-click test, `returnSpeed` 0.01 m/s so a snap can't be mistaken for spring-back). The debug fingertip presses to the stop (fires, disarmed), then the local player is teleported 10 m away. The button snaps to rest at once (press 0, at the rest position), engagement is cleared, it's re-armed and `outOfRange` is set. While away, pulling the tip out and pushing it back in registers nothing and doesn't fire. Back in range, the tip left inside doesn't engage; from the front it presses and fires again (2 action logs). A 1 s click teleported away part-way is cut off (click cleared, press 0, no fire). Teleporting back leaves the player in range, at rest and armed. "Walking" away is a ClientSim teleport. UdonSharp compiled 10 scripts with no errors. Result: `[PushButtonTest] done: 333 passed, 0 failed`, 0 errors (the trigger again only left Play Mode at "time up").
