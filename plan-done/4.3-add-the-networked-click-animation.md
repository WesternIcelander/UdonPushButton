# 4.3 Add the networked click animation

`Interact()` now sends the network event to `Others` after starting the local click. `NetPlayClickAnimation()` returns early when the local player is farther than `AnimationRangeSqr` from `transform.position` (a null local player counts as in range), and otherwise calls `StartClickAnimation(false)`. It doesn't look at VR status. **Extra guard:** if a *local* click is still pressing in (`clickActive && clickIsLocal`), the event is ignored, so another player's click arriving at the same moment can't turn the local click non-local and swallow its action. 6.1's range gate will also cover the out-of-range case each frame; this check stops a far-away event from starting a click in the first place. Added `AddNetClickTest` to the harness (instead of a temporary debug call inside `PushButton`). It calls `SendCustomEvent("NetPlayClickAnimation")` on the button's UdonBehaviour with `clickPressDuration` 1 s and `returnSpeed` 0.01 m/s, and checks: a non-local click starts; the press 0.4 s in matches the animation (0.0076 measured and expected); afterwards it reached the bottom and is springing back (0.0150), the click has ended, the button is still armed, and nothing fired. It then checks the button returns to rest. Finally it moves the parent 20 m away, sends the event again, and checks that no click starts, the button stays at rest, and nothing fires. Result: 0 action logs, `[PushButtonTest] done: 109 passed, 0 failed`, 0 errors. ClientSim has no remote clients, so the actual network delivery to other players is left for 9.3 (formerly 8.3).
