# 9.3 Run the multi-client and VR test (built world, 2+ clients, headset)

## Scene setup

The demo scene now shows every feature, so the built world can test them:

- `PushButtonAssembly/Button` has `releaseEventName` `OnButtonReleased`, `anyonePressedEventName` `OnAnyonePressed` and `anyoneReleasedEventName` `OnAnyoneReleased`.
- `PushButtonManager` has `allowVRTrigger` on.
- `PushButtonAssembly 2` is a copy of the assembly 0.3 m to the side (world +X), inactive in the scene. Its button calls its own `ButtonActionExample` with the same events and uses the same manager. The first assembly's `ButtonActionExample.toggleTarget` points at it, so pressing Button 1 shows Button 2 on the presser's client only. That makes it the "starts disabled, enabled after B joins" button.

This was set up by a one-off editor script (duplicated with `Unsupported.DuplicateGameObjectsUsingPasteboard`, fields set on the proxies and copied with `CopyProxyToUdon`). The script was deleted afterwards, and `Fix Manager Wiring` ran before the save. No text UI was added.

The Play Mode tests were written for the old defaults. `AddSceneWiringTest` now checks the new wiring through `CheckDemoWiring`, then resets it for the rest of the run: empty release and anyone events, `allowVRTrigger` off, no `toggleTarget`. Without that reset, 14 checks failed. For example, clicks switched on Button 2, so 11 buttons ticked instead of 10. The inspector test's two "scene button's events left empty" checks were dropped, since the scene wiring test covers those values now. Result: `[PushButtonTest] done: 1590 passed, 0 failed`. Build check: `114 passed, 0 failed`.

## Run

Uploaded through the editor trigger (`upload: done`) and started profile 0 (Siggі) in VR and profile 2 (Kötturinn) on desktop in the group test instance. The developer did each case by hand and reported that everything worked. Cases covered:

- VR finger push by Siggі, seen on desktop Kötturinn; haptics on both index fingers; no false presses from reaching past the button.
- VR trigger click and trigger hold by Siggі, seen on Kötturinn (the hold stays down until released).
- Desktop click and held click by Kötturinn, seen on VR Siggі.
- Button 2 shown after Kötturinn joined, then pushed in VR and seen animating on the other client.
- Viewer more than 5 m away: no animation and no errors.

Client logs: 29 `pressed by Siggі` and 29 `released by Siggі` lines only on Siggі's client, and 5 `pressed by Kötturinn` and 5 `released by Kötturinn` lines only on Kötturinn's client. Each client logged 34 `anyone pressed` and 34 `anyone released` lines, so every press and release (29 + 5) logged the anyone events once on each client. Neither log had any Udon exceptions. The only errors were VRChat client noise (Amplitude, OSC, Discord, StyleEngine).

## Not covered

- **VR push seen by a VR viewer:** this needs two headsets, and there is one. Whether a button animates doesn't depend on the viewer's platform (the same remote-bone path draws it for desktop viewers), and a VR viewer did see desktop clicks animate.
- **Mobile held tap:** no mobile client was in the run, so it's still unknown whether a held tap releases when the finger lifts.
