# 5.4 Apply the per-player VR filter

in `UpdateFingertipPresses`, a tracked player's fingertips are estimated and evaluated only if `Utilities.IsValid(player) && player.IsUserInVR()`. Otherwise all their slots are cleared, the same way as for an invalid player. The check uses each player's own `IsUserInVR()` every frame, for the local player too, and never the viewer's `localIsVR`, so a remote VR player's push moves the button on desktop and VR viewers alike. `debugFingertip` is still evaluated separately, whatever the local platform. **Code review against [Who sees what](../PLAN.md#who-sees-what):** the VR presser row holds, because the presser's `IsUserInVR` is true on every viewer and the viewer's platform isn't checked. The desktop presser row is unchanged: their avatar's hands never press, and their click comes through `NetPlayClickAnimation`, which has no VR check. The action row is unchanged: only `localPress` and the local click reach `UpdateTrigger`. **Harness:** ClientSim players are all desktop, so the tests swap `VRCPlayerApi._IsUserInVR` from ClientSim's handler to `SimulatedIsUserInVR`, which reports chosen player IDs as in VR. `SimulateVR(player, bool)` controls it, and the swap is undone on `ExitingPlayMode`. `localIsVR` (input mode) is set in `Start` before the swap, so the input-mode test still sees desktop. `AddFingertipTest` marks the local player as VR first, and the later tests run with it on, as they did in 5.3. `AddRemotePressTest` marks its remote player as VR. New `AddVRFilterTest`: a local VR fingertip pressing half-way releases (engaged and in-front cleared, `localPress` 0) once the local player is switched to desktop. A desktop local fingertip neither registers in front nor engages when pushed in, while `debugFingertip` still presses (0.0095) on desktop. A desktop remote fingertip pushed 0.03 m in gives `remotePress` 0 and leaves the button at rest. After switching that remote player to VR, the same push engages from the front and reaches the stop (0.0190). UdonSharp compiled 10 scripts with no errors. Result: `[PushButtonTest] done: 275 passed, 0 failed`, 0 errors (the trigger again only left Play Mode at "time up").
