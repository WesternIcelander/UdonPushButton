# 8.11 Add "anyone pressed" and "anyone released" events

## What was done

- `PushButton`:
  - New `anyonePressedEventName` and `anyoneReleasedEventName` in `Action`, under `releaseEventName`, both empty by default.
  - **Presser's side.** `AnnounceToAnyone(name, netEvent)` sends the event to `targetBehaviour` here, then `SendCustomNetworkEvent(Others, netEvent)`. A null or empty name, or no target, sends nothing, locally or over the network. `UpdateTrigger` calls it for anyone pressed right after `FireAction`, so it comes after the press event and before an immediate release (an action that resets the button). `FireRelease` calls it for anyone released after the release event. Every release path (use-up, re-arm, reset mid-press) goes through `FireRelease`, so every anyone pressed is followed by one anyone released. `FireRelease` no longer returns early when the release event is unset, so the anyone events fire whether or not `eventName` and `releaseEventName` are set.
  - **Receivers.** `NetAnyonePressed()` / `NetAnyoneReleased()` send the matching event to the target. They're ignored unless `IsLive()` (enabled, registered, manager running), as networked clicks are. There's no range or VR check. Remote finger presses and networked clicks never reach `UpdateTrigger`'s fire path, so they never announce.
- `PushButtonEditor`: both new fields use the optional event dropdown with "(none)".
- `ButtonActionExample`: new `OnAnyonePressed` / `OnAnyoneReleased`, logging `[ButtonActionExample] anyone pressed` / `anyone released`. The scene button leaves both names empty.
- Tests:
  - New `AddAnyoneEventsTest` (`PushButtonPlayModeTests.AnyoneEvents.cs`), run after the hold test.
  - `CountActionLogs` adds the anyone logs to `actionOrder` (not to the press and release counts).
  - The inspector test now expects the example's four events, and checks that the two fields follow `releaseEventName` under `Action` and that the scene button leaves them empty.

## How it was checked

- `refresh` + `Re-compile All Program Sources`: UdonSharp compiled 11 scripts with no errors.
- `AddAnyoneEventsTest`, with network events recorded through the `SendCustomNetworkEventProxy` hook:
  - **Fingertip:** press logs `pressed, anyone pressed` and sends one `NetAnyonePressed`. The release adds `released, anyone released` and one `NetAnyoneReleased`.
  - **Held click:** sends `NetPlayClickAnimation, NetAnyonePressed`. On the use-up it adds `NetReleaseClick, NetAnyoneReleased`, with the logs in the same order as for a fingertip.
  - **No press or release event set:** the anyone events and their network events still fire.
  - **Received:** calling `NetAnyonePressed` / `NetAnyoneReleased` directly logs only the anyone event, sends nothing, and leaves the button at rest, armed, with nothing pending.
  - **Remote:** a remote VR player's fingertip pressing the button to the stop, and a remote player's networked click and release, log nothing and send nothing.
  - **Null and empty names:** a fingertip press logs only `pressed, released`, received events log nothing, nothing is sent over the network, and no errors are logged.
  - **Disabled:** received events are ignored while the button is disabled and while the manager is disabled. They're received again once both are back on.
  - **Disabled mid-hold:** a held click, then disabling the button, logs anyone released once and sends one `NetAnyoneReleased`. Turning the button back on and releasing the input adds nothing.
- Full Play Mode run: `[PushButtonTest] done: 1586 passed, 0 failed`, 0 errors logged.
- Left for 9.3: whether a network event sent while the presser's button is disabling (the release on a mid-hold disable) reaches other clients in a real build. ClientSim's hook records the send, but it can't show delivery.
