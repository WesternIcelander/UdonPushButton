# 10.2 Add the editor assembly

## What was done

- Moved `PushButtonEditor.cs`, `PushButtonBuildCheck.cs` and `PushButtonWiring.cs`, each with its `.meta`, from `Assets/PushButton/Editor/` to `Packages/io.siggi.pushbutton/Editor/` with `git mv`. GUIDs are unchanged.
- Added the editor-only `Editor/SiggiPushButton.Editor.asmdef`. It references `SiggiPushButton`, `VRC.SDKBase`, `VRC.SDKBase.Editor.BuildPipeline`, `VRC.SDK3`, `VRC.Udon`, `UdonSharp.Runtime` and `UdonSharp.Editor`, like `SiggiUSTools.SimpleI18nEditor.asmdef`. No `rootNamespace`, since the classes are in the global namespace.
- Removed the test-only static hook `PushButtonBuildCheck.testAnswer`. The build check now takes its question's answerer through an `internal` constructor. The public parameterless constructor (which the SDK uses) asks with the dialog. `RunCheck` in the build-check tests now builds `new PushButtonBuildCheck(answer)`. So the shipped class keeps no global test state.
- Added `Editor/AssemblyInfo.cs` with `InternalsVisibleTo("Assembly-CSharp-Editor")`, where the tests still live, for `WiringWarning`, `GetEventNames` and the answer constructor. **10.4 must change it to the new test assembly's name.**
- Dropped the mention of the test menu `Tools/PushButton/Wire Up Scene` from `PushButtonWiring`'s doc comment, since that menu isn't part of the package.
- The `Check Manager Wiring` and `Fix Manager Wiring` menu items are unchanged.

## How it was checked

- `refresh`, then `Re-compile All Program Sources`: no compile errors, and `Library/ScriptAssemblies/SiggiPushButton.Editor.dll` was built.
- Build-check tests: `[PushButtonBuildCheckTest] done: 114 passed, 0 failed`. They call `OnBuildRequested` the way a world build does.
- Full Play Mode run: `[PushButtonTest] done: 1590 passed, 0 failed`, `Play Mode ended, 0 errors logged`. The counts are the same as before. The run checks that `PushButton`'s inspector is `PushButtonEditor` (plan step 7.1) and that it draws every field.
- No upload was done. The SDK finds `IVRCSDKBuildRequestedCallback` implementations across all loaded assemblies (its own sample callback is in a package assembly too), so moving the class to a package assembly doesn't hide it. A real upload in 10.5 or later checks this end to end.
