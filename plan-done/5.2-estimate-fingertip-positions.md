# 5.2 Estimate fingertip positions

UdonSharp has no `out` parameters, so `GetFingertips(player)` fills preallocated private buffers: `fingertipPositions` (`Vector3[4]`), `fingertipValid` (`bool[4]`, in the same slot order as the state arrays: left index, right index, left middle, right middle) and `fingertipScaledRadius`. `EstimateFingertip` does one slot: distal + `(distal - intermediate) * FingertipExtrapolation` (0.8). If either finger bone is missing (`GetBonePosition` returns zero) it uses the hand bone instead, and the slot is invalid only if the hand is missing too. Disabled fingers (`useIndexFingers` / `useMiddleFingers`) are invalid. The radius is `fingertipRadius * eyeHeight / ReferenceEyeHeight` (1.6), or unscaled if the eye height isn't positive. A temporary hook in `Update` (marked `TEMP (plan step 5.2)`) runs `GetFingertips` on the local player each frame, so the tests can read the buffers. Step 5.3 should replace it with the per-player loop. **Gizmo:** in Play Mode, `OnDrawGizmosSelected` now also draws a green wire sphere of the scaled radius at each valid fingertip of every tracked player. It reads `trackedPlayers` from Udon and runs `GetFingertips` on the editor proxy (using the proxy's own finger toggles). Added `AddFingertipTest` to the harness. It compares Udon's buffers with an estimate from the local ClientSim avatar's bones: index slots valid and middle off by default (0.00 mm from expected, finger bones present, so no hand fallback), and the tip lies past the distal bone. The radius is scaled by the eye height (ClientSim 1.9 m → 0.0095). Turning index off and middle on flips the slots. A 1 m teleport moves both tips by exactly (1, 0, 0), and the player is teleported back afterwards. Result: `[PushButtonTest] done: 166 passed, 0 failed`, 0 errors. The hand-bone fallback isn't exercised, because the ClientSim avatar has all its finger bones.
