# 8.8 Move the shared settings to the manager

## What was done

- `PushButtonManager` now has `fingertipRadius`, `useIndexFingers`, `useMiddleFingers`, `hapticStrength` (under `VR`), `clickPressDuration` (under `Desktop`) and `debugFingertip` (under `Debug`), with the old defaults and tooltips.
- `PushButton` lost those Inspector fields. `interactText` stays, still under `Desktop` (8.9 moves it). The button keeps `[NonSerialized] public` copies of the five settings, and its tick reads only those.
- The manager writes the settings into a button in `Register`, before it sets `registeredWithManager`. Buttons register on every enable, and 8.4's `TryRegister` retries until the manager has started, so a button never ticks before it has the manager's values. That holds at scene load too.
- `ApplySettings()` writes them into every registered button, and into any registration waiting until the tick ends. Disabled buttons pick them up when they're next enabled.
- The manager decides on its own finger choice which finger bones to read. The union over in-range buttons and the `activeUseIndex` / `activeUseMiddle` scratch arrays are gone. A button counts as active for the hand check unless the manager uses no finger at all.
- Debug fingertip: the button reads `manager.debugFingertip` inside `#if UNITY_EDITOR`, so builds have no read and no debug path. The old `#if !UNITY_EDITOR debugFingertip = null` in `Initialize` is gone. Each button keeps its own `debugEngaged` / `debugWasInFront`.
- Gizmos: the fingertip spheres take the radius and finger choice from the running button's copies.
- Custom inspector: unchanged code. It draws every visible serialized field, so the moved fields simply aren't there any more.
- Scene: a throwaway menu item (deleted afterwards) wrote the scene button's saved values onto the scene's manager (0.008, index on, middle off, 0.3, 0.12, no debug tip; all defaults), copied both proxies to Udon and saved. UdonSharp also marked the button's backing UdonBehaviour `m_ObjectHideFlags: 2`, its usual inspector-hiding flag.
- Tests: new helpers `Setting(name)` / `SetSetting(name, value)` read the scene manager's setting, or set it and call `ApplySettings`. `PlaceDebugTip` / `RemoveDebugTip` put the debug fingertip on the scene manager. Every test that set a moved field on a button now sets it on the manager. The two enable/disable cases that used to slow down only a clone's click now slow it down globally and put it back at the end.

## How it was checked

- `refresh` + `Re-compile All Program Sources`: no C# errors, and UdonSharp compiled 11 scripts.
- New `AddSettingsTest` (`PushButtonPlayModeTests.Settings.cs`), with the scene button and a clone 8 cm beside it:
  - after `ApplySettings` with non-default values (radius 0.02, middle only, haptics 0.7, click 0.8 s), both buttons hold all five values, both click over 0.8 s, and on each one the debug fingertip, placed for a half press with the new radius, gives a local press of exactly half the travel;
  - a `clickPressDuration` change without `ApplySettings` leaves both buttons unchanged; once the clone is disabled and enabled again it has the new value, and the scene button still doesn't;
  - restoring the values reaches both buttons;
  - the debug fingertip pressing one button leaves the other with no local press and nothing engaged, both ways round;
  - scene load: a new holder with a copy of the button first and a copy of the manager after it, the manager's saved Udon data holding the non-default values, the button's pointing at that manager. Both are initialized button first, so the button's first registration attempt is dropped. An editor-frame watcher checks the button's copies the moment it is registered: all five match. It then clicks over the saved 0.8 s.
- Inspector test: the button's visible serialized fields no longer include any moved field, and `interactText` is still there.
- Full Play Mode suite: `[PushButtonTest] done: 1410 passed, 0 failed`, 0 errors (1385 before, plus 23 settings checks and 2 inspector checks). A temporary per-check log confirmed all 23 settings checks ran. The final run, after removing the log and the migration script, gave the same result.
- Edit Mode build-check suite: `[PushButtonBuildCheckTest] done: 114 passed, 0 failed`.
- Not checked: haptic strength through a real VR press (the test checks the value reaching both buttons; the 5.5 haptics test still covers the pulse through the manager's setting).
