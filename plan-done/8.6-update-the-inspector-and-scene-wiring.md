# 8.6 Update the inspector and scene wiring

## What was done

- New `Assets/PushButton/Editor/PushButtonWiring.cs`: the shared wiring code, meant for 8.7's build check to use too.
  - `FirstManager()`: the first `PushButtonManager` in hierarchy order across the loaded scenes (scenes in load order, root objects in scene order, then depth first), inactive ones included.
  - `AllButtons()`: every `PushButton` in the loaded scenes, inactive ones included.
  - `Problem(PushButton, first)`: why a button isn't wired, or null. It reads the manager from the proxy and from the UdonBehaviour's data (`publicVariables` in Edit Mode, the live program variable in Play Mode). The decision itself is `Problem(proxyManager, udonManager, first)`, which tests can call directly. These count as unwired: no manager in the scene, a null proxy manager, a proxy manager that isn't the first one, and Udon data that isn't the first manager's backing UdonBehaviour.
  - `Fix()`: adds a `PushButtonManager` GameObject at the root of the active scene if there's none, wires every unwired button (`SerializedObject` + `CopyProxyToUdon`, with Undo), and saves the scenes it changed. It doesn't ask. It does nothing in Play Mode or when there are no buttons, and returns how many buttons it wired.
- `PushButtonEditor`: below the `manager` field it shows a warning box with the problem when any selected button isn't wired, plus a **Fix** button that runs `PushButtonWiring.Fix()`. The button is turned off in Play Mode, and Fix runs after `ApplyModifiedProperties`. `WiringWarning(Object[])` is `internal static` so tests can use it.
- `Tools/PushButton/Wire Up Scene` now gets its manager through `PushButtonWiring.Fix()`, and its own `FirstManager` is gone.
- Running Wire Up Scene again re-saved the scene. The diff is only Unity/SDK normalization: the newer public fields (`fingerCheckLocalCenter`, `fingerCheckRangeSqr`, `registeredWithManager`) copied into the button's Udon data, `_syncMethod` normalized on a behaviour, and two network IDs added to the `PipelineManager`. The wiring itself didn't change.

## How it was checked

- `refresh` + `Re-compile All Program Sources`: UdonSharp compiled 11 scripts, with no C# errors.
- New `AddManagerWarningTest` (run as part of the inspector test), on the scene button:
  - no warning with the scene's manager, and the decision returns null for the right manager;
  - with the proxy's `manager` set to null, or to a second `PushButtonManager` on an inactive GameObject, `WiringWarning` shows a warning; once the field is restored it doesn't, and a later manager doesn't change `FirstManager`;
  - the decision also warns for a null manager, null Udon data, Udon data pointing at another UdonBehaviour, and no manager in the scene.
- The existing `AddSceneWiringTest` still checks that the button is wired to the root `PushButtonManager`, and that a ClientSim desktop click logs once.
- Full suite: `[PushButtonTest] done: 1385 passed, 0 failed` (up from 1373), 0 errors. It ran once before and once after re-saving the scene with Wire Up Scene.
- Not checked: clicking the Fix button in the inspector GUI. Nobody was at the PC. `Fix()` itself ran through Wire Up Scene (nothing to wire, so it made no wiring change). 8.7's Edit Mode tests will exercise `Fix()` on unwired scenes.
