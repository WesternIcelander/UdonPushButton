# 8.2 Cache fingertips once per player per frame

**Manager:** new public `[NonSerialized]` per-slot cache: `slotValid`, `slotIsLocal`, `slotInVR`, `slotLeftHand`/`slotRightHand`, `slotNear`, `slotScale` (eye height / 1.6, 1 when unknown), and `fingertipPositions`/`fingertipValid` (slot × 4 + finger, in the old order: left index, right index, left middle, right middle). `PrepareFrame()` builds it, but only on the first call in a `Time.frameCount`, so every button calls it and the work happens once. For each valid VR player it reads both hand bones and the eye height. If either hand is within a registered, active button's hand check sphere (a missing hand bone counts as near, as before), it sets `slotNear` and estimates both hands' fingertips, only for the fingers those near buttons use (the union of their `useIndexFingers`/`useMiddleFingers`). The fallback to the hand bone reuses the hand position it already read. Non-VR players get nothing, so the VR filter is now the manager's. The constants `FingertipsPerPlayer`, `HandEarlyOutDistance` (public), `FingertipExtrapolation` and `ReferenceEyeHeight` moved to the manager. **Registration (minimal; 8.3/8.4 finish it):** `Register`/`Unregister` (idempotent, an ordered array that doubles from 8). A button registers lazily in its first `Update` (so both programs are initialized) and unregisters in a new `OnDisable`. The manager also drops destroyed buttons (`Utilities.IsValid`) as it finds them. **Button:** `GetFingertips`, `EstimateFingertip`, `HandNear` and the per-button fingertip buffers and scaled radius are gone. New public `[NonSerialized]` fields the manager reads: `fingerCheckActive` (true while registered and in range; false when the range gate trips and on disable), `fingerCheckCenter` (the contact box centre in world space, set each in-range frame before `PrepareFrame`) and `fingerCheckRangeSqr` (was `handEarlyOutRangeSqr`). `UpdateFingertipPresses` reads each manager array once per frame. A slot presses only if `slotNear`, and a fingertip only if this button uses that finger and it's valid. The radius is `fingertipRadius × slotScale`, and local/remote comes from `slotIsLocal`. A far hand's fingertips are now cleared by the manager's `slotNear` (or by leaving the footprint) instead of a per-button hand check, with the same results in the tests. Other buttons' check spheres are from their last frame (whichever button calls `PrepareFrame` first). 8.3 removes that one-frame lag when the manager ticks the buttons. The editor fingertip gizmo now draws the manager's cached tips that this button uses. **Harness:** `AddFingertipTest`/`CheckFingertips` read the local player's slot from the manager's `fingertipPositions`/`fingertipValid` (new `LocalCachedTips`), and the radius check uses `fingertipRadius × slotScale`. "Middle only" still sees index invalid, since the manager only estimates fingers a near button uses. New `AddBoneReadCountTest` (after the hand early-out test) swaps ClientSim's `_GetBonePosition` for a per-frame counter (restored at the end and on leaving Play Mode). The local player is in VR, with the scene button 2 cm in front of their left index. 1 button: 6 reads every frame (2 hands + 2 index fingers × 2 bones). Then 9 clones are made in a 5 × 2 grid 6 cm apart (`Object.Instantiate` plus `InitializeUdonContent`, which ClientSim doesn't call for instantiated objects). All 10 have `fingerCheckActive`, and the count is still 6 every frame. With every button 1 m above the hands it's 2 (hands only). The clones are then destroyed. UdonSharp compiled 11 scripts with no errors. Result: `[PushButtonTest] done: 704 passed, 0 failed` (up from 691), 0 errors.
