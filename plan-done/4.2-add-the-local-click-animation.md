# 4.2 Add the local click animation

`Interact()` calls `StartClickAnimation(true)`, which sets private `clickActive`, `clickIsLocal` and `clickStartTime = Time.time` (a new click restarts the animation). Each frame `UpdateClickPress()` sets `clickPress = travelDistance * elapsed / clickPressDuration`. Once the time is up it holds `travelDistance` for exactly one frame (so the trigger sees the bottom), then clears `clickActive` and drops `clickPress` to 0, and `UpdatePressAmount` springs the button back at `returnSpeed`. A `clickPressDuration` of 0 or less goes straight to the bottom. `Update` now passes `max(localPress, clickIsLocal ? clickPress : 0)` to `UpdateTrigger`. For 4.3, `NetPlayClickAnimation` only needs to call `StartClickAnimation(false)`. **Behaviour note:** re-arming follows the *local* press, so the button re-arms as soon as the click releases, while it is still visibly springing back. A quick second click fires again, which seems right for a click. Added `AddClickTest` to the harness, and moved the trigger test's target setup and teardown into `SetUpActionTarget` / `TearDownActionTarget`. The test clicks through the button's `ClientSimUdonHelper.Interact()` (the same call ClientSim's own interact makes), with `clickPressDuration` set to 1 s and `returnSpeed` to 0.01 m/s. It checks the press 0.4 s in (0.0076 measured, 0.0076 expected, no fire yet), then 0.4 s after the bottom: fired once, click released, re-armed, springing back at the expected rate (0.0150). It restores the speeds and checks the button is back at rest, then does a second click at the default speeds, which fires once more and returns to rest. Result: 2 action logs, `[PushButtonTest] done: 94 passed, 0 failed`, 0 errors. Nobody clicked by hand, and the animation wasn't watched; it was checked from the Udon variables and the transform.
