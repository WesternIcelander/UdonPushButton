# 8.13 Add a method to change the interaction text

## What was done

- **Button.** Added `public void SetInteractText(string text, bool isI18nKey = false)` and a private `interactTextIsLiteral` flag. The method sets `interactText` and the flag, then calls `_UpdateInteractive`, which reads I18n only when the flag is off and the button is listening. It sends nothing over the network.
- **Warning.** A key on a button with no I18n logs a warning on each such call. An empty or null key doesn't warn, since there's nothing to translate.
- **Never-enabled buttons.** Udon drops the call, so the button keeps its saved text. The plan allowed for this, and the method's doc comment says so.
- **Test caller.** UdonSharp fills in an omitted optional argument where the call is compiled, so testing the one-argument call needs a compiled caller. Added the test-only `Assets/PushButtonTests/PushButtonTestCaller.cs` and its program asset. They aren't in the package.
- **Tests.** New `PushButtonPlayModeTests.SetInteractText.cs` (`AddSetInteractTextTest`). `MakeI18nButton` is now split so a test can keep a button unstarted (`MakeUnstartedI18nButton`, `StartI18nButton`).

## How it was checked

- `refresh`, then `Re-compile All Program Sources`. UdonSharp accepted the optional parameter, and `PushButtonTestCaller` compiled and ran with all three call forms.
- Full Play Mode run: `[PushButtonTest] done: 1734 passed, 0 failed`. `Play Mode ended, 1 errors logged`: the one error is the expected `[I18n] No string found for key no_such_key`.
- Build-check tests: `[PushButtonBuildCheckTest] done: 114 passed, 0 failed`.
- The tests cover each case in the plan's check, all in ClientSim. The first run showed the never-enabled call being dropped (`got "Test text"`, the saved key's translation), so that test now expects it.
