# 10.4 Move the tests into their own assembly

## What was done

- Renamed `Assets/PushButton/` to `Assets/PushButtonTests/` with `git mv` (folder `.meta` files included), so every test file keeps its GUID. The Play Mode tests, the build-check tests and their menu items (`Run Tests On Next Play`, `Wire Up Scene`, `Run Build Check Tests`) now live in `Assets/PushButtonTests/Editor/`, and `Assets/PushButton/` is gone.
- Added the editor-only `PushButtonTests.Editor` asmdef. It references both package assemblies (`SiggiPushButton`, `SiggiPushButton.Editor`), plus `SiggiPushButton.Example` because `Wire Up Scene` adds `ButtonActionExample` by type. It also references `VRC.SDKBase`, `VRC.SDKBase.Editor.BuildPipeline`, `VRC.SDK3`, `VRC.Udon`, `VRC.ClientSim`, `UdonSharp.Runtime` and `UdonSharp.Editor`. The precompiled Udon DLLs (`VRC.Udon.Common` and others) are auto-referenced.
- `InternalsVisibleTo` in `Packages/io.siggi.pushbutton/Editor/AssemblyInfo.cs` now names `PushButtonTests.Editor` instead of `Assembly-CSharp-Editor`.
- `ButtonProgramPath` and `ExampleProgramPath` already pointed into the package (from 10.1 and 10.3), so they stay as they are. Updated the test path in `TestingAutomation.md` (not in git).

## How it was checked

- The project compiled with no errors, and `Library/ScriptAssemblies` holds `PushButtonTests.Editor.dll`. UdonSharp: `Compile of 15 scripts finished`.
- Full Play Mode run: `[PushButtonTest] done: 1590 passed, 0 failed`, `Play Mode ended, 0 errors logged`. That's the same count as in 10.3.
- Build-check tests: `[PushButtonBuildCheckTest] done: 114 passed, 0 failed`, also the same as before.
