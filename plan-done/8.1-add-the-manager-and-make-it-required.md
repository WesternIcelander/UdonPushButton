# 8.1 Add the manager and make it required

`PushButtonManager.cs` plus a hand-written `PushButtonManager.asset` (UdonSharp filled in its compiled fields). The manager keeps public, `[NonSerialized]` arrays `slotPlayers` (null marks a free slot) and `slotGenerations`. They start empty, grow to 8 on the first player and double when full. `OnPlayerJoined` puts the player in the first free slot (or one holding an invalid player) and bumps that slot's generation. Joining is idempotent, so the `OnEnable` rebuild and the join events can't add anyone twice. `OnPlayerLeft` frees the player's slot. `OnEnable` rebuilds from `GetPlayers`: it frees slots whose player is gone and adds anyone missing. `FindSlot(player)` is public. On `PushButton`: there's a new `manager` field under a `Setup` header. The player list and join/leave handlers are gone. The per-fingertip state (`fingertipEngaged`/`fingertipWasInFront`) is now indexed by manager slot, with a new `seenGenerations` per slot. `MatchSlotCount` grows these arrays when the manager's do. `UpdateFingertipPresses` walks `manager.slotPlayers` and clears a slot's fingertip state when its generation changed. Fingertip estimation, the VR filter and the early-out are still on the button (8.2 moves them). With no manager, `Start` still caches the rest pose and contact box, then logs `[PushButton] <name>: no manager is set, so the button does nothing` and sets `DisableInteractive = true`. `Update`, `Interact` and `NetPlayClickAnimation` return straight away when `manager` is null. The editor fingertip gizmos read the players from the manager. The inspector shows `manager` automatically, since it draws every visible property. **Scene:** to keep the suite passing, part of 8.6 was done now. `Tools/PushButton/Wire Up Scene` creates a `PushButtonManager` GameObject at the scene root if the scene has no manager (otherwise it uses the first in hierarchy order, via `FirstManager`) and sets the button's `manager`. That menu item was run and the scene saved. UdonSharp also changed `ButtonActionExample`'s backing `_syncMethod` from 0 to 2 (Unity-generated). **Harness:** `SlotOf`, `CheckTrackedPlayers` and `CheckLocalFingertipKept` now use the manager's slots. `CheckTrackedPlayers` checks the number of occupied slots against `GetPlayerCount()`, no duplicates, all valid, the local player present, a generation per slot, and four button state entries per slot. `AddSceneWiringTest` also checks that the button is wired to a root-level `PushButtonManager`. New `AddManagerSlotsTest` (after player tracking): remote F and G join and F leaves. F's slot is freed and G keeps its own. Then H joins and takes F's slot with generation +1 (slot 1, generation 2 → 3). New `AddNoManagerTest` (before the inspector test) builds a `PushButtonTestNoManager` at runtime: a BoxCollider plus an UdonBehaviour running `PushButton.asset` with no variables set. It isn't interactive, and ClientSim's `CanInteract` is false. A direct `Interact()` and a `NetPlayClickAnimation` do nothing. The debug fingertip from in front to 1.5× travel gives no local press, no engagement and no movement. The button stays armed, and exactly 1 warning is logged. UdonSharp compiled 11 scripts with no errors. Result: `[PushButtonTest] done: 691 passed, 0 failed` (up from 627), 0 errors. **Trigger note:** this `play` didn't leave Play Mode when the done text was logged; it waited out its 240 s. With a single wait text, `EditorTrigger.OnLog` crosses it off by setting `waitFor` to `""`, which the update loop reads as "no texts" instead of "all logged". That's a bug in the skill's trigger. It doesn't change any result. A workaround is to wait for two texts, e.g. `play 240 [PushButtonTest] done|passed`.
