# 8.3 Let the manager drive the buttons

**Manager:** `AnimationRange`/`AnimationRangeSqr` moved here (public consts). Each registered button now has a cached `Transform` and an in-range flag, in parallel arrays that grow and shift with `buttons`. `Register` now returns `bool` (true, also when it's already registered). New `Update` runs three steps. (1) `UpdateRangeGates` (replaces `CollectActiveButtons`) drops destroyed buttons and checks each button's current `transform.position` against the local player. A missing local player counts as in range. An out-of-range button is at rest, and an in-range one is at most its travel from rest, so this matches the old rest-pose check to within 1.9 cm. A button leaving range gets `_LeaveRange()` once. Each in-range button that uses a finger adds its hand check sphere, centred at `transform.TransformPoint(fingerCheckLocalCenter)`. (2) `PrepareFrame(activeCount)` is now private, with no frame stamp, and runs before any button ticks, so the one-frame lag from 8.2 is gone. (3) It calls `_Tick()` on each in-range button that's still valid and stores the count in public `[NonSerialized] tickedButtons`. A new registration starts flagged in range, so a button that starts out of range gets the reset once, as before. **Button:** `Update` and `UpdateRangeGate` are gone. `_Tick()` clears `outOfRange` and does rest pose, fingertip presses, click, trigger, press amount and apply. `_LeaveRange()` is the old out-of-range reset; it also re-reads the rest pose before snapping to it. `fingerCheckActive`/`fingerCheckCenter` are replaced by `fingerCheckLocalCenter` (the BoxCollider/mesh centre in local units). Registration moved from the first `Update` to `Start` and to `OnEnable` after `Start`. Udon drops calls to a behaviour it hasn't started yet (`RunEvent` before `_hasDoneStart`), which happens when a button starts before the manager in the first frame. So `TryRegister` checks `Register`'s return value and, on false, retries next frame with `SendCustomEventDelayedFrames(_RetryRegister, 1)` (only while enabled). A no-manager button never registers, so it never ticks. **Left for 8.4:** deferring register/unregister while the manager is ticking (an action that disables a button now unregisters it straight away, inside the loop), first-enable init in `OnEnable`, the disable reset, and the manager-disabled rules. A dropped `Register` while the manager is disabled could also read a stale `true` return value. **Harness:** the bone-read test's "10 buttons in range" now uses `!outOfRange` (new `InRange` helper) and also checks `tickedButtons == 10` (new `TickedButtons` helper). New `AddManagerTickTest` (after the bone-read test) uses a desktop local player. It clones the scene button 9 times beside it (5 × 2 grid, 6 cm apart) and 40 times onto a holder 20 m away (8 × 5 grid). Checks: 10 ticked per frame, 10 in range, the 40 out of range and at rest. Then near clone 0 is pressed to the bottom with its own debug fingertip: it's at full travel, and none of the other 49 buttons moved or have a press. Still 10 ticked. After destroying the clones, only the scene button ticks. UdonSharp compiled 11 scripts with no errors. Result: `[PushButtonTest] done: 716 passed, 0 failed` (up from 704), 0 errors (run with `play 240 [PushButtonTest] done|passed`, the trigger workaround from 8.1).
