# 8.5 Skip transform writes when nothing changed

**Button:** new `appliedPress` (starts at -1) holds the press `ApplyPress` last wrote. `ApplyPress` returns straight away when asked for that same amount, so a button whose press doesn't change (at rest, or held at the bottom) stops writing `transform.position`. `ResetToRest()` sets `appliedPress = -1` before its `ApplyPress(0f)`, so every enable, disable, range leave and manager disable writes the rest pose once, even when the press was already 0 (the parent may have moved while the button was off). Spring-back ends exactly at 0 (`MoveTowards`), so a released button stops writing as soon as it's back. Skipping is safe with a moving or turning parent: the button is its child, the written offset is fixed in the parent's space, and Unity carries it along. One gap: if the parent's scale changes while the button is held at a constant non-zero press, the offset scales with it until the press next changes. The engagement math still rebuilds the rest pose every tick. **Harness:** new `AddTransformWriteTest` in `PushButtonPlayModeTests.Manager.cs`, run after `AddEnableDisableTest`. With `transform.hasChanged` cleared on the in-range, ticked scene button: at rest for 1 s it hasn't changed; pressed to the bottom by the debug fingertip, released and sprung back to rest (checked at the bottom and rest positions) it has; at rest for 1 s again it hasn't; moving the parent 10 cm up and back puts the button at the new rest pose each time.
