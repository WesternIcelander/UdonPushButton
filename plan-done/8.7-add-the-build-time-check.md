# 8.7 Add the build-time check

## What was done

- New `Assets/PushButton/Editor/PushButtonBuildCheck.cs`, an `IVRCSDKBuildRequestedCallback`. On a world (`Scene`) build request it runs the check and always returns true. Avatar builds are skipped.
  - `Run(Func<string, bool> ask)` is the decision logic. The dialog (`EditorUtility.DisplayDialog`, **Fix** / **Not Now**) is passed in as `ask`, and `internal static testAnswer` replaces it in tests. It returns `NothingToFix`, `Fixed` or `Declined`.
  - No buttons: nothing happens. No manager: one question, and on yes `PushButtonWiring.Fix()` adds the manager, wires every button and saves. Unwired buttons (judged by `PushButtonWiring.Problem`, proxy and Udon data): one question giving the count, and on yes `Fix()`. On no, nothing changes. Nothing happens in Play Mode.
  - With several managers, every check logs a warning naming the one used (by hierarchy path) and the ones ignored.
  - Menu items: `Tools/PushButton/Check Manager Wiring` runs the same check with dialogs and logs `[PushButton] manager wiring is fine` when there's nothing to ask. `Tools/PushButton/Fix Manager Wiring` gives the same several-managers warning, then runs `Fix()` without asking.
- `PushButtonWiring`: added `AllManagers()` (hierarchy order, inactive ones included). `FirstManager()` and `AllButtons()` now share the same scene walk.
- Automated builds run `menu Tools/PushButton/Fix Manager Wiring` before `upload`. The skill and its trigger are unchanged.

## How it was checked

- `refresh` + `Re-compile All Program Sources`: no C# errors. UdonSharp compiled 11 scripts.
- New Edit Mode tests in `Assets/PushButton/Editor/PushButtonBuildCheckTests.cs`, run with `save`, then `menu Tools/PushButton/Run Build Check Tests`, then reading the Editor log. Each case builds a fresh scene saved to `Assets/PushButtonBuildCheckTest.unity`, calls `OnBuildRequested(Scene)` with the test hook answering, and checks the result. Afterwards the open scenes are restored with `RestoreSceneManagerSetup` and the temporary scene is deleted. The run refuses to start if an open scene has unsaved changes. Cases:
  - no buttons: asks nothing and adds no manager;
  - no manager + yes, with an active button, an inactive one and one under an inactive parent: asks once, adds one `PushButtonManager` at the root, wires all three (proxy and Udon data), saves the scene, and a second run asks nothing;
  - no manager + no: asks once, and there is still no manager and both stored values are null;
  - correctly wired, inactive buttons included: asks nothing;
  - null manager, second manager, proxy set but Udon data null, and Udon data on the second manager (the broken button inactive, next to a wired one): each asks once. Yes wires it to the first manager and saves; no leaves both stored values as they were;
  - two managers, the first in hierarchy order nested under an earlier root though created last: the warning names it and the ignored one on every check (unwired and wired), and the button is wired to it.
  - Every case checks that the callback returned true.
  - Result: `[PushButtonBuildCheckTest] done: 114 passed, 0 failed`.
- Each switch to an empty test scene logs an `IndexOutOfRangeException` from the VRChat SDK control panel's own `OnSceneChanged` (`VRCSdkControlPanelWorldBuilder.CreateValidationsGUI`, a scene without a scene descriptor). This is SDK noise, not from this code, and the tests aren't affected.
- Afterwards `git status` showed the main scene unchanged and the temporary scene gone.
- Full Play Mode suite: `[PushButtonTest] done: 1385 passed, 0 failed`, 0 errors.
- Both menu items on the real scene: Check logged `manager wiring is fine`, Fix changed nothing.
- Not checked: the real dialog in a Build & Test / Build & Upload from the SDK panel (nobody at the PC). The callback itself was called directly in the tests.
